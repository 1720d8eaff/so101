# 实验方案

## 语言条件多任务操作

在同一硬件和任务定义下比较 SmolVLA、ACT 与 Diffusion Policy。SmolVLA 接收语言指令；ACT / Diffusion Policy 是模仿学习对照，不因共享相同采集记录就成为 VLA。

评测分别记录固定任务、语言改写、目标位置变化、物体组合和中途扰动。各组使用预先固定的任务 / 初始条件清单，报告实际样本量、模型检查点与训练种子。训练和调参使用的数据不能混入最终测试清单。

建议分阶段运行：环境与数据校验 → 短训练验证检查点可加载 → 基线训练 → 同预算对照 → 真机评测。每个阶段的实际日志、配置、耗时与结果另行保存；不能用本仓库的命令预览替代实际运行证明。

## Sim2Real

目标比较纯真机训练、纯仿真训练、仿真预训练后真机微调。当前仓库提供数据校验与训练入口；未包含 SO-101 场景模型、专家规划器、仿真自动 rollout 或仿真到 LeRobot 的数据转换。

接入仿真时需要提供：

1. 明确来源与许可的 URDF / MJCF、关节范围、夹爪控制定义和相机标定。
2. 场景与任务成功条件，以及可记录失败 episode 的专家 / 规划策略。
3. 对物体与目标位置、相机外参、光照及动力学参数的随机化实现；种子与采样值随 episode 保存。
4. 状态、动作、RGB、末端位姿及任务结果导出器；验证单位、时序与训练格式。
5. 仅训练数据计算的统计量与仿真 / 真机一致的特征定义。

没有以上输入时，不把现成的其他机械臂仿真称作 SO-101 Sim2Real。预训练后的继续训练需要明确优化器状态与归一化 processor 的加载方式，不能仅把另一份数据路径填进基础训练命令就视作完成迁移实验。

准备好仿真预训练检查点后，`training.init_policies.diffusion` 可指向对应 `pretrained_model` 目录，修改 `dataset` 为真机数据并换用新的 `training.output_root`，再运行 `train-diffusion`。这是从已有权重开始的新训练，未启用 optimizer resume；验证动作定义与归一化 processor 的兼容性后才能用于迁移对照。ACT 的初始化检查点也可通过 `init_policies.act` 指定。

## ACT 双臂基线

双臂 Transfer Cube 应单独维护官方 ACT 仿真环境、轨迹划分和初始状态清单。本仓库 `train-act` 面向 LeRobot 格式的 SO-101 操作数据，不直接运行官方双臂仿真。

研究示范噪声与平滑时，保留原始轨迹和验证集，先明确受扰动关节与夹爪通道。离线修改动作标签不会同步生成新的观测，须在报告中说明这个限制。

`so101-augment` 已实现按选定通道加高斯噪声与因果 EMA：噪声标准差为 `scale × train_std`，默认 scale 0.05、alpha 0.5。首帧使用原始 noisy 首帧；每次调用只处理一条 episode。当前不做关节限制裁剪，不能将输出直接当作经过硬件约束校验的真机目标。
